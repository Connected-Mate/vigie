Four watch posts, one report

A single lookout only sees one slope. Vigie cross-checks four public databases, with no account and no key, and gives one answer sorted by urgency.

  • The smoke

    OSV.dev

    Known vulnerabilities and malicious packages in open source packages, matched on your exact version. Run by Google and OpenSSF, it gathers advisories from GitHub, PyPA, RustSec, Go and others.

  • The fire

    CISA KEV

    The catalogue of vulnerabilities already exploited in real attacks. If one of yours is in it, Vigie marks it “act now”.

  • The wind

    EPSS

    A score updated daily by FIRST.org: how likely a vulnerability is to be exploited soon. It tells you which way a fire might spread.

  • The regional bulletin

    CERT-FR

    The latest alerts and advisories from ANSSI, the French government agency. Recent bulletins only.

What the lookout actually does

It watches, it warns, it says where to go. Your agent does the rest.

  1. 01

    It stops the burning tree at the gate

    Before an npm install, pnpm add, yarn add, pip install, uv add or poetry add, the hook checks the packages. If one has a high-priority known vulnerability or is malicious, the install is blocked and the agent gets the report and the fix.

  2. 02

    It scans the whole forest

    Give it a project folder: Vigie reads its dependency files (package-lock.json, pnpm-lock.yaml, yarn.lock, requirements.txt, poetry.lock, uv.lock, Cargo.lock, go.mod…) and checks every version it finds.

  3. 03

    It gives the exact spot and the way out

    The check is on your exact version, not just the package name. For each affected package, a “What to do” line names the version to move to.

  4. 04

    It never calls “all clear” in the fog

    A database that does not answer is named in the report. If the check could not be done, the verdict is “incomplete”, and the agent has to tell you.

  5. 05

    It watches beyond the trees too

    PostgreSQL, nginx, Windows Server: for what is not a package, a keyword watch brings up recent CERT-FR bulletins and vulnerabilities exploited in real attacks.

  6. 06

    A simple tower you can walk through

    Plain Node.js, no dependency, nothing to npm install. No account, no key. Short enough to read before you trust it.

Three steps to raise the tower

Your agent does them for you with the setup prompt. If you would rather do them yourself, here they are.

  1. Connect the MCP server

    Clone the repository, then declare Vigie in your agent. This is what gives it the checking tools.

  2. Set the hook

    It checks packages before each install and the project after each edit of a dependency file. This is what makes the check mandatory.

  3. Add the rule

    Three lines in your agent instructions (CLAUDE.md, AGENTS.md…): check before adding a dependency, check before saying “done”, tell you when the check is incomplete.

What the lookout cannot see

A lookout tower does not replace the fire crew, or looking after the forest. Here are its blind spots, stated plainly.

  • It only sees smoke that has been reported

    Vigie only knows publicly disclosed vulnerabilities in published packages. It does not find flaws in your own code, misconfiguration, or vulnerabilities nobody has reported yet.

  • The regional bulletin only keeps recent issues

    CERT-FR only exposes its latest bulletins. The keyword watch matches product names, not your exact version: an empty answer proves nothing.

  • Without a detailed map, it only sees the forest edge

    With package.json alone and no lockfile, indirect dependencies are not checked. Vigie says so in the report.

  • In the fog, the gate stays open

    If the databases are unreachable, the hook lets the command through and says so. To block instead, set VIGIE_STRICT=1.

  • The first round of the day takes a moment

    The first call of the day downloads the catalogues: about 30 seconds. After that, results are kept on your machine.

Frequently asked questions

Is it really free?

Yes. Vigie is free, open source (MIT license), with no account and no key. The four databases it asks are public and free as well.

What exactly does Vigie check?

Known vulnerabilities and malicious packages in the packages your project uses, on their exact version. For each one: whether it is exploited in real attacks, how likely it is to be soon, whether a CERT-FR bulletin exists, and which version to move to.

What does Vigie not see?

Anything that is not a public vulnerability in a published package: flaws in your own code, misconfiguration, vulnerabilities not reported yet. With package.json alone, indirect dependencies are not checked. And CERT-FR only gives its latest bulletins. A report with no finding does not mean your project is safe.

What leaves my machine?

The names and versions of your packages, and the public ids of the vulnerabilities found, sent to the public databases it asks. Never your code. You can verify it: Vigie's code is short and readable.

Which agents does it work with?

The server works with any MCP-compatible agent: Claude Code, Codex, Cursor and others. The hook that blocks installs is written in the Claude Code hook format. With another agent, you still get the checking tools and the rule in its instructions.

Which languages are covered?

Package by package: npm, PyPI, Maven, Go, crates.io, NuGet, Packagist and RubyGems. For a project folder, Vigie reads package-lock.json, pnpm-lock.yaml, yarn.lock, package.json, requirements.txt, poetry.lock, uv.lock, Cargo.lock and go.mod. The hook recognises installs made with npm, pnpm, bun, yarn, pip, uv and poetry.

What if a database is down?

It is named in the report. If an older copy exists on your machine, Vigie uses it and says so. If OSV.dev does not answer, the verdict is “incomplete”, never “all clear”. The hook then lets the command through, unless VIGIE_STRICT=1 is set.

Does it slow my agent down?

The first call of the day downloads the catalogues, which takes about 30 seconds. After that, results are cached in ~/.cache/vigie.

How do I remove it?

Undo the three install steps: remove the MCP server from your agent, take the hook out of its settings, delete the rule from its instructions. You can then delete the Vigie folder and ~/.cache/vigie. Your agent can do it for you.

Why “Vigie”?

“Vigie” is French for a lookout: the watch post, and the person keeping it. Like a fire lookout in a tower, the tool does not fight the fire: it spots it early and tells the crew, your agent, where to go and what to do.
